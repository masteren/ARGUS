ARGUS ER図（SQLite / argus.db・全6テーブル）

会員登録・チケット購入（模擬決済）から、チケット消費・ロボット命令の実行完了・ミッション成功までを利用者単位で1本の履歴として追跡できる構造

erDiagram
    users        ||--o{ purchases     : "購入するたびに1件"
    users        ||--o{ transactions  : "チケットを使うたびに1件"
    transactions ||--|| command_queue : "取引1件につき命令1件を発行"
    transactions ||--o| missions      : "search_person のときだけ生成"
    command_queue ||--o| missions     : "巡回命令を保持(command_id)"
    detections   ||--o| missions      : "成功の根拠となった検出(detection_id)"

    users {
        INTEGER id PK "自動採番"
        TEXT name UK "表示名 24文字まで（ランキングにも使う）"
        TEXT pin_hash "4桁PINのハッシュ（平文は保存しない）"
        INTEGER balance "チケット残高（0以上）"
        TEXT created_at "登録日時"
        TEXT last_login_at "最終ログイン日時"
    }

    purchases {
        INTEGER id PK "自動採番"
        INTEGER user_id FK "users.id"
        TEXT payment_id "模擬決済ID dummy_xxxx"
        TEXT pack "pack_500 / pack_1000"
        INTEGER tickets "加算したチケット枚数 500/1000"
        INTEGER price "表示価格（模擬円・実際の請求なし）"
        TEXT status "paid"
        TEXT created_at "購入日時"
    }

    transactions {
        INTEGER id PK "自動採番"
        INTEGER user_id FK "users.id（消費した利用者）"
        TEXT payment_id "取引ID（残高から支払い）"
        TEXT timestamp "取引日時"
        INTEGER amount "消費チケット枚数 100/300/500"
        TEXT action "forward/turn_left/turn_right/bow/wave/search_person"
        TEXT action_label "前進 / お辞儀 など表示名"
        TEXT payer_name "users.name の写し（ランキング集計用）"
        TEXT message "応援メッセージ 100文字まで"
        TEXT status "paid"
        TEXT created_at "登録日時"
    }

    command_queue {
        INTEGER id PK "自動採番"
        INTEGER transaction_id FK "transactions.id"
        TEXT action "実行する動作コード"
        TEXT action_label "表示名"
        TEXT source "発行元。現状は paid のみ（/pay が登録）"
        TEXT status "pending → done"
        TEXT created_at "登録日時"
        TEXT done_at "完了報告を受けた日時"
    }

    missions {
        INTEGER id PK "自動採番"
        INTEGER transaction_id FK "transactions.id"
        INTEGER command_id "command_queue.id（論理参照）"
        TEXT action "search_person"
        TEXT action_label "人を探す"
        TEXT payer_name "依頼した利用者名"
        TEXT status "active → success"
        TEXT created_at "開始日時"
        TEXT success_at "成功日時"
        INTEGER detection_id "detections.id（論理参照）"
    }

    detections {
        INTEGER id PK "自動採番"
        TEXT timestamp "検出日時"
        TEXT type "person / mission_person"
        REAL confidence "信頼度 0.0〜1.0"
        TEXT image "静止画ファイル名"
        TEXT bbox "検出枠 [x1,y1,x2,y2] JSON"
        TEXT frame_wh "映像解像度 [w,h] JSON"
        TEXT created_at "登録日時"
    }

主キー：全テーブル id INTEGER PRIMARY KEY AUTOINCREMENT／外部キー制約：command_queue.transaction_id・missions.transaction_id → transactions(id)、purchases.user_id・transactions.user_id → users(id)（CREATE TABLE で宣言）。ただし SQLite は既定で外部キーを強制しないため、実際の整合はアプリ側で保つ。
論理参照：missions.command_id・missions.detection_id は制約を宣言せず、アプリ側（/pay・/upload）で整合を取る。
残高の整合：users.balance は「purchases.tickets の合計 − transactions.amount の合計」と常に一致する。消費は UPDATE users SET balance = balance - ? WHERE id = ? AND balance >= ? と取引・命令の登録を同一トランザクションで確定させ、残高が負になる消費は 402 で拒否する。
payer_name を残す理由：ランキング・ボード・ミッション表示は従来どおり payer_name で集計・表示する。登録時の名前を書き写すので、画像認識（A）と音声・実機（C）の側は変更不要。
金額について：チケットは模擬通貨で、1チケット＝¥1〈模擬〉として表示する。実際の金銭は発生しない。実決済へ差し替える場合は purchases.payment_id と status を決済事業者の値に置き換える。
