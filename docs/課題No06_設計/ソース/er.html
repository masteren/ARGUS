ARGUS ER図（SQLite / argus.db・全4テーブル）

体験チケット（模擬通貨）の消費から、ロボット命令の実行完了・ミッション成功までを1本の履歴として追跡できる構造

erDiagram
    transactions ||--|| command_queue : "取引1件につき命令1件を発行"
    transactions ||--o| missions      : "search_person のときだけ生成"
    command_queue ||--o| missions     : "巡回命令を保持(command_id)"
    detections   ||--o| missions      : "成功の根拠となった検出(detection_id)"

    transactions {
        INTEGER id PK "自動採番"
        TEXT payment_id "模擬決済ID dummy_xxxx"
        TEXT timestamp "取引日時"
        INTEGER amount "消費チケット枚数 100/300/500"
        TEXT action "forward/turn_left/turn_right/bow/wave/search_person"
        TEXT action_label "前進 / お辞儀 など表示名"
        TEXT payer_name "利用者名 24文字まで(未入力は匿名)"
        TEXT message "応援メッセージ 100文字まで"
        TEXT status "paid"
        TEXT created_at "登録日時"
    }

    command_queue {
        INTEGER id PK "自動採番"
        INTEGER transaction_id FK "transactions.id"
        TEXT action "実行する動作コード"
        TEXT action_label "表示名"
        TEXT source "発行元。現状は paid のみ（/pay が登録）"
        TEXT status "pending → done"
        TEXT created_at "登録日時"
        TEXT done_at "完了報告を受けた日時"
    }

    missions {
        INTEGER id PK "自動採番"
        INTEGER transaction_id FK "transactions.id"
        INTEGER command_id "command_queue.id（論理参照）"
        TEXT action "search_person"
        TEXT action_label "人を探す"
        TEXT payer_name "依頼した利用者名"
        TEXT status "active → success"
        TEXT created_at "開始日時"
        TEXT success_at "成功日時"
        INTEGER detection_id "detections.id（論理参照）"
    }

    detections {
        INTEGER id PK "自動採番"
        TEXT timestamp "検出日時"
        TEXT type "person / mission_person"
        REAL confidence "信頼度 0.0〜1.0"
        TEXT image "静止画ファイル名"
        TEXT bbox "検出枠 [x1,y1,x2,y2] JSON"
        TEXT frame_wh "映像解像度 [w,h] JSON"
        TEXT created_at "登録日時"
    }

主キー：全テーブル id INTEGER PRIMARY KEY AUTOINCREMENT／外部キー制約：command_queue.transaction_id・missions.transaction_id → transactions(id)（CREATE TABLE で宣言）。ただし SQLite は既定で外部キーを強制しないため、実際の整合はアプリ側で保つ。
論理参照：missions.command_id・missions.detection_id は制約を宣言せず、アプリ側（/pay・/upload）で整合を取る。
会員テーブルを置かない理由：会員登録・ログインは Ver1.0 のスコープ外。利用者は毎回入力する payer_name で識別し、ランキングは payer_name の合計で集計する。
金額について：amount は体験チケット（模擬通貨）の枚数であり、実際の金銭は発生しない。実決済へ差し替える場合は transactions.payment_id と status を決済事業者の値に置き換える。
