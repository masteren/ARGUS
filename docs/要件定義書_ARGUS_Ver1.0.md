## 1. プロジェクト概要

### 1-1. 背景

HEW の主題は「お金が動く Web サービス」である。ARGUS は市販の6脚ロボット（Freenove ＋ Raspberry Pi 5、歩行制御は公式コードを無改造で使用）に、自作の **AI レイヤ（画像認識・音声対話）** と **IoT レイヤ（Flask＋SQLite＋取引処理＋Web）** を載せた作品であり、後者がその主題に直接あたる。実際の金銭は動かさず、来場者に配布する**体験チケット（模擬通貨）**で取引を再現する。

### 1-2. 目的

観客は来場時に**体験チケット（模擬通貨）**を受け取り、それを消費して目の前の実機ロボットへ指示を出す。**「チケット消費 → 取引記録 → 命令キュー → 実行 → 完了記録」の全経路が後から追跡できる**状態で、指示した動作が数秒後に現実で起きる体験を成立させる。

### 対象プラットフォーム（利用端末・ブラウザ）

観客：スマートフォン（iOS Safari / Android Chrome、縦画面）で公開ページを利用／運営：PC の Chrome で管理ダッシュボードを利用／サーバ：PC または Raspberry Pi 5 上の Flask＋SQLite。**会場ローカル LAN のみで動作し、インターネット公開は行わない。**

## 2. 機能要件

### 2-1. Ver1.0 対象機能（スコープイン）

| # | 機能名 | 機能の説明（何ができるか） | 優先度 |
| --- | --- | --- | --- |
| 1 | AI 人物検出とライブ映像 | カメラ映像を配信し、観客がチケット不要で視聴できる。AI が人物を検出して時刻・信頼度・静止画・枠座標を保存し、映像の上に検出枠を重ねて表示する | 高 |
| 2 | チケット消費と取引記録 | 名前とアクションを選んでチケットを使うと取引が1件永続化される。未定義のアクションは受け付けない。利用者別の累計ランキングを公開し、運営は検出・取引・命令を1画面で確認できる | 高 |
| 3 | チケット→動作の実行閉ループ | 取引成立と同時に命令キューへ登録され、ロボットが取得して実行し、完了報告で `done` になる。ロボットへ渡すのは成立した取引に紐づく命令のみとする | 高 |
| 4 | 「人を探す」ミッション | チケット消費でミッションが `active` になりロボットが巡回し、AI が人物を発見すると `success` と成功時刻が記録される | 高 |
| 5 | 音声対話と音声操作 | 話しかけると1〜2文で応答し、「何が見える？」には最新の検出結果を参照して答える。動作語は即座に実機へ送る | 中 |

### 2-2. Ver1.0 対象外機能（スコープアウト）

| # | 機能名 | 対象外とした理由 |
| --- | --- | --- |
| 1 | 実際の金銭決済（本番カード決済・返金） | 体験チケットで主題を再現でき、本番決済の責任を負えないため。データ構造は差し替え可能にしておく |
| 2 | 会員登録・ログイン | その場の観客が数十秒で参加する体験であり、登録の摩擦が体験価値を損なうため |
| 3 | 自律走行・顔認識による個人特定・インターネット公開・録画保存・多言語 UI | 歩行は公式コードを無改造で使う方針であり、その他も展示期間中の価値に寄与せず、リスクと実装コストだけが増えるため |

> ※ 体験チケットは紙で配布し、**重複使用の防止は運営の目視確認で行う**。券番号の発行と
> システム側での使用済み判定は Ver1.0 では実装しない。

## 3. 非機能要件

| # | 機能名 |
| --- | --- |
| 1 | 性能：取引 API は1秒以内に応答し、チケット消費から実機動作の開始までを5秒以内とする |
| 2 | 可用性：3モジュールは独立して起動・停止でき、サーバ停止中も他モジュールは異常終了せず復旧後に自動再開する |
| 3 | セキュリティ・データ整合性：アクションのホワイトリスト検証と入力検証を行い、取引・命令・ミッションを時刻付きで永続化して相互に追跡できる |
| 4 | 保守性・運用：モジュール間 API は `CONTRACT.md` を正本とし、実機なしで閉ループを1コマンドで回帰検証できる。ネット不通でも主経路は動作し、体験チケットが模擬通貨であることを明記する |
